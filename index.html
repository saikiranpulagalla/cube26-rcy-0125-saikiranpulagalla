Recovery Manager

A deterministic, evidence-driven financial recovery engine that distinguishes money that appears missing from money that is actually justified and currently actionable for recovery.

UNKNOWN ≠ ZERO

Missing evidence is not proof. Unknown reconciliation is not zero. Historical validity is not automatically current actionability. And one entitlement must not be recovered twice.

View GitHub Repository

How it works

1 · Canonicalize

Financial source records become tenant-scoped canonical events and obligations.

2 · Prove

Evidence and synthetic authority must support the exact recovery proposition.

3 · Reconcile

Linked settlements and active recovery pursuits reduce the remaining economic residual.

4 · Decide safely

Supported cases may become claim-ready. Unknown or unsupported cases fail closed to REVIEW.

Residual economics

E = justified gross entitlement

C = net linked settlement

U = E - C

A = active pursuit allocation

R = U - A = remaining actionable residual

Engineering boundaries

The authoritative monetary decision path is deterministic and evidence-constrained. An LLM does not determine financial entitlement.

PostgreSQL provides tenant isolation through row-level security and separate application, worker, and owner roles. Decision publication is guarded, and historical decision-time provenance is preserved independently from current actionability.

Scope

Recovery-policy mechanics are synthetic. This project does not claim official Amazon recovery-policy accuracy, guaranteed reimbursement, or live Amazon claim filing.
